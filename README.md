# Rage of Fight

> **تفکیک پروژه‌ها:** برنامهٔ ریشهٔ مخزن یک پروتوتایپ مستقل با **Three.js + Vite + Capacitor** است؛ پروژهٔ Unity بازسازی‌شده از APK اصلی در `unity-reconstruction/` قرار دارد. این دو را با هم اشتباه نگیر.

پروتوتایپ شوتر اول‌شخص موبایل‌محور با رابط فارسی و پایهٔ **Three.js + Vite + Capacitor** است. هدف محصول، ساخت یک شوتر کامل و مستقل در ژانر بازی‌هایی مثل Counter-Strike، Zula و Call of Duty است؛ این نام‌ها فقط مرجع ژانر/کیفیت‌اند، نه اجازه یا برنامه‌ای برای کپی نام، نقشه، ظاهر یا دارایی‌هایشان. نسخهٔ فعلی هنوز prototype است. برای جلوگیری از شروع از صفر، سه مدل سلاح، مدل ثابت زامبی و صداهای شلیک/خشابِ استخراج‌شده از APK اصلی به runtime وصل شده‌اند؛ نگاشت و provenance آن‌ها در [`public/recovered/README.md`](public/recovered/README.md) است. استخراج از APK مجوز انتشار این دارایی‌ها را ثابت نمی‌کند. شبه‌کدهای `recovered/apk-beta-native/` سورس قابل‌کامپایل Unity نیستند و در بازی استفاده نشده‌اند.

## قابلیت‌ها

- **تمرین آفلاین:** شش ربات مسلح با تیراندازی از فاصله، خط دید، احتمال خطا و respawn؛ مسیر‌یابی روی navmesh برای دورزدن پوشش ثابت.
- **مسابقهٔ تیمی آفلاین (نمونهٔ اولیه):** پنج‌به‌پنج با ربات‌ها، امتیاز تیمی، ساعت، جدول حذف/مرگ، kill feed، بازپیدایی امن و پایان مسابقه بر اساس امتیاز/زمان. ربات TDM پس از آسیب، در صورت وجود مسیر و پوشش مناسب، برای مدت کوتاه به پناه نزدیک عقب می‌رود؛ این رفتار تاکتیکی پایه است، نه AI رقابتی کامل. هنوز آنلاین نیست و جایگزین تست LAN نمی‌شود.
- **بقای زامبی آفلاین:** موج‌های پیوسته با تعداد، سلامتی، سرعت و آسیب رو‌به‌افزایش؛ سقف تعداد زامبی هم‌زمان برای گوشی.
- **Graybox نقشه:** آرنای رویه‌ای با علامت‌های رنگی spawn دو تیم و حلقهٔ مرکزی؛ این نشانه‌ها تزئینی‌اند و layout هنوز نهایی نیست.
- **شبکهٔ محلی آزمایشی:** یکی از گوشی‌ها میزبان TCP می‌شود و تا چهار گوشی دیگر با IP دستی می‌پیوندند. وضعیت دشمن‌ها و موج‌ها روی میزبان مرجع است؛ موقعیت بازیکن‌ها و آسیب گلوله بین دستگاه‌ها ردوبدل می‌شود. اتصال اینترنت لازم نیست.
- **سلاح‌ها:** تفنگ تهاجمی، تپانچه و شات‌گان؛ خشاب، شارژ مجدد، لگد، پراکندگی، افت آسیب با فاصله و هدشات.
- **کنترل موبایل:** حرکت با جوی‌استیک لمسی و نگاه با کشیدن انگشت در نیمهٔ راست صفحه؛ دکمه‌های شلیک، پرش، خشاب و تعویض سلاح. حساسیت نگاه در ماوس و لمس اعمال می‌شود.
- **تنظیمات محلی:** حساسیت نگاه، میدان دید، صدای اصلی و پروفایل گرافیکی خودکار/عملکرد/کیفیت با ذخیره در همین دستگاه؛ حالت خودکار روی لمس سایه‌ها را خاموش می‌کند و وضوح رندر را محدود نگه می‌دارد.
- **رابط فارسی:** منو، وضعیت بازی، موج و اعداد فارسی/راست‌چین.

> شبکهٔ محلی فعلاً آزمایشی است و هنوز روی دو گوشی فیزیکی آزموده نشده. هر دو گوشی باید به یک وای‌فای وصل باشند؛ در منوی میزبان IP نمایش‌داده‌شده را در گوشی مهمان وارد کن. اگر روتر گزینهٔ client/AP isolation دارد، باید خاموش باشد. LAN در پیش‌نمایش وب کار نمی‌کند؛ از APK اندروید استفاده کن.
>
> TDM پنج‌به‌پنج فعلاً صرفاً یک vertical slice آفلاین است. هنوز نقشهٔ هنری، انیمیشن کامل، ضدتقلب، matchmaking یا سرور اینترنتی نداریم؛ LAN فعلی هم برای رقابت عمومی امن نیست.

## اجرا در وب

نیازمندی: Node.js 20 یا جدیدتر.

```bash
npm install
npm run dev
```

آزمون قوانین مسابقه، تیم‌بندی AI، موج‌ها، مسیر‌یابی navmesh و همگام‌سازی snapshotها:

```bash
npm test
```

ساخت وب:

```bash
npm run build
npm run preview
```

## ساخت APK آزمایشی اندروید

برای build محلی، Node.js 22، JDK 21 و Android SDK با platform/build-tools 36 لازم است. پوشهٔ Android در این مخزن حاضر است؛ آزمون، همگام‌سازی و build را اجرا کن:

```bash
npm ci
npm test
npm run build
npx cap sync android
cd android
./gradlew --no-daemon assembleDebug
```

APK محلی در `android/app/build/outputs/apk/debug/app-debug.apk` ساخته می‌شود. Workflow [`android-debug-apk.yml`](.github/workflows/android-debug-apk.yml) همین مراحل را در GitHub Actions پس از push به شاخهٔ کاری یا اجرای دستی انجام می‌دهد؛ APK آزمایشی با نام `rage-of-fight-debug-apk` به مدت ۱۴ روز به‌صورت artifact نگه‌داری می‌شود. Build موفق جایگزین نصب و QA روی گوشی واقعی نیست.

## اتصال LAN

1. APK را روی هر دو گوشی نصب کن و هر دو را به **یک شبکهٔ Wi-Fi** وصل کن.
2. در گوشی اول «میزبانی بازی» را بزن؛ IP و پورت `24180` نمایش داده می‌شود.
3. در گوشی دوم «پیوستن به میزبان» را بزن، IP نمایش‌داده‌شده را وارد کن و اتصال را انتخاب کن.
4. پس از ظاهرشدن گوشی مهمان در فهرست میزبان، میزبان حالت تمرین یا بقا را انتخاب و بازی را شروع می‌کند.
5. تا وقتی صفحهٔ بازی میزبان باز است، گوشی میزبان را در پیش‌زمینه نگه دار. این نسخه بازیابی اتصال پس از قطع Wi-Fi یا background شدن برنامه را تضمین نمی‌کند.

اگر اتصال برقرار نشد، IP هر دو گوشی و خاموش‌بودن guest/client isolation روتر را بررسی کن. پورت ثابت LAN برابر `24180/TCP` است.

## ساختار پروژه

- `src/main.js` — صحنه، ورودی، حلقهٔ بازی، منو و جریان LAN
- `src/World.js` — آرنای تمرین، موانع، نورها، pickupها، محل spawn و هندسهٔ navmesh
- `src/Navigation.js` — ساخت navmesh ایستای Recast و مسیریابی ربات‌ها
- `src/MatchSession.js` — قوانین مستقل تیم‌مرگ‌ومیر: clock، امتیاز، برنده و مساوی
- `src/Player.js` — حرکت، برخورد و سلامتی بازیکن
- `src/Weapon.js` — سه سلاح، مدل‌های recovered و ثبت اصابت
- `src/SoundEffects.js` — صدای شلیک/خشاب بازیابی‌شده با fallback تولیدی و صدای اصلی قابل‌تنظیم
- `src/GameSettings.js` — تنظیمات محلی، اعتبارسنجی محدوده و ذخیره‌سازی امن
- `src/recoveredAssets.js` — نگاشت دارایی‌های APK و شناسه‌های منبع
- `public/recovered/` — مدل‌های OBJ سلاح و زامبی، تکسچرها و صداهای متصل به بازی
- `src/EnemyManager.js` — رفتار ربات‌ها، زامبی‌ها، موج‌ها و snapshot شبکه
- `src/LanTransport.js` — پل JavaScript برای افزونهٔ بومی LAN
- `android/app/src/main/java/com/rageoffight/game/LanMultiplayerPlugin.java` — میزبان TCP و اتصال مهمان اندروید
- `src/NetworkPlayers.js` — مدل‌های بازیکن‌های راه‌دور
- `src/HUD.js` — رابط وضعیت فارسی
- `test/gameModes.test.js` — آزمون‌های موج، AI و همگام‌سازی LAN
- `test/navigation.test.js` — آزمون مسیر‌یابی دور موانع در نقشهٔ Graybox
- `test/matchSession.test.js`, `test/teamDeathmatch.test.js` — قوانین Match، تیم‌بندی و AI مسابقهٔ تیمی
- `test/gameSettings.test.js`, `test/soundEffects.test.js` — اعتبارسنجی تنظیمات و سطح صدای اصلی
- `test/recoveredAssets.test.js` — آزمون مسیرها، فرمت و parse شدن دارایی‌های بازیابی‌شده
- `docs/asset-register.md` — وضعیت حقوقی دارایی‌ها و برنامهٔ آرت مستقل/مجاز
- `docs/phase-1-device-qa.md` — چک‌لیست نصب و QA روی گوشی واقعی
- `THIRD_PARTY_NOTICES.md` — مجوزهای کدهای متن‌باز استفاده‌شده

فایل‌های `recovered/apk-beta-native/` فقط برای بررسی ساختار APK بتا هستند؛ آن‌ها سورس قابل‌کامپایل Unity یا جایگزین سورس این پروتوتایپ نیستند.

## بازسازی پروژهٔ اصلی Unity

پروژهٔ Unity مبتنی بر APK اصلی در [`unity-reconstruction/`](unity-reconstruction/README.md) نگهداری می‌شود. این یک بازسازی دارایی‌ها و metadata است؛ APK با IL2CPP سورس اصلی C# را حفظ نمی‌کند. شبه‌کد native بازیابی‌شده در [`Assets/Recovered/NativePseudocode/`](unity-reconstruction/Assets/Recovered/NativePseudocode/README.md) برای بازرسی است، نه سورس قابل‌کامپایل یا بازی کامل و آزموده‌شده. برای بازکردن، Unity `2022.3.62f1` لازم است؛ دستور ساخت صحنه‌ها در README همان پروژه آمده است.
